# ADR 0003：以修正后的 fork 作为完整提取来源

日期：2026-10-30。状态：用户已确认；fork 修复已提交推送，F 来源准备与 Rust/C++ helper 同步已实现。完整调用链/原生验收及本地历史整理尚未完成。影响阶段：P1 来源与实现、P2 来源冻结与完整提取验收；P3–P6 编号与职责不变。

本 ADR 替代[原计划](../plans/maafw-screencap-extraction-plan.md)中“先完成未修复 U，再于 P2 应用固定旧 PR 得到 P”的来源与实施顺序。它同时更新 R1–R8、[ADR 0001](0001-gdi-virtual-desktop-capture.md)及 [ADR 0002](0002-native-interface-modernization.md)中的阶段引用，不替代其语言、绑定、图像、扩展或发布决策，也不改写历史证据。

## 背景与决定

[PR #1587 的成员评审](https://github.com/MaaXYZ/MaaFramework/pull/1587#issuecomment-6492173498)指出旧 head `f603a04633b0e43a8bbcb94ddef60fc349ad29a1` 的两个问题：全局 rcMonitor 校正会允许普通窗口客户区落入任务栏区域；外窗口四边 ±8px 容差会放过真实越界的客户区，使桌面复制裁剪失败。用户选择先修改 fork，再把等价修复同步到新项目的完整提取环节。

完整提取基线改记为 **F**：来源是 `AbyssRei/MaaFramework` 的确切提交 `a434521e7f49cff97f92117add554038b523eef9`、tree `06b7e7f32b5b644e706c530945a12c03b7f1f4e7`，不是滚动分支名。原 MaaFramework `0fc6025c2fc224a171b57d89505e8d47acd2a8b1` 保留为来源祖先和范围比较依据；旧 PR 两条提交及其累计差异只作历史来源。新增第三条修复提交保留了前两条历史；相对祖先的累计差异仅含 HwndUtils.hpp 及三份独立 window_geometry 测试文件。来源已锁定不表示 F 已完整验收。

P1 直接迁移修正 fork 的全部截图职责，修复进入 HwndUtils/窗口几何迁移及其实际调用链。P2 改为来源冻结、完整提取与专项回归的汇总验收，不再应用第二次 PR 补丁。P3 在验收后的 F 上建立产品 E；共享租约、严格 SDK 几何、原生接口现代化和其他产品扩展仍按原阶段实施。

## 修复边界

- 普通窗口继续按 `rcWork` 校正；保留原调整优先级、最大化/最小化豁免及 `SetWindowPos` flags。
- 沿现有 `WS_POPUP` 判据，只有客户区的屏幕矩形四边精确等于选定显示器 `rcMonitor` 时跳过校正；先完成客户区及屏幕坐标查询，不用外窗口 ±8px 容差代替客户区判断。
- 客户区有任何偏移、尺寸不符或越界时不获得该豁免，继续原工作区校正；查询失败保持原错误路径。保留调用线程 DPI 上下文，不把此修复扩展为新的全屏、置顶或独占模式识别。
- 参考程序和 Rust 使用相同修正版语义，保留像素转换时点、等待/回放、native 生命周期、方法选择、窗口观察及退出行为。其他来源差异必须逐项审查，不能顺便换成最新 upstream。

## 来源与证据

新建 `baselines/f/<baseline-id>/` 和 `patches/pr-1587/<revision-id>/` 记录，绑定原始祖先、fork URL、确切 head/tree、实际提交列表、累计差异、每份源码/适配及 Rust 快照的哈希。来源工具必须支持按显式修订验证历史与新版记录；不能只替换全局 HEAD 常量，使旧批次无法校核。真实格式和校验代码随实现落入 xtask；目录和清单不因本 ADR 提前创建。

既有 `baselines/u/`、`baselines/p/`、旧 `patches/pr-1587/` 文件及运行记录保持原身份和结果，不覆盖、不更名为 F。现有 P0 准备结论保留其原范围，F 的新增来源准备另行记录。源码未变且输入/配置及证明范围仍匹配的历史切片可在映射中引用；受影响的几何 helper、ScreenDC、DesktopDupWindow、manager/factory 转发须用新版来源重新验收，不直接继承旧通过结果。原生失败、缺失环境、跳过和通过继续分开记录。

## 历史组织与执行交接

用户提出本地历史重写：修复及相关参考/测试/来源调整应位于 P1 提取阶段，不能作为 P3 或更晚的产品增强。可放入相关迁移提交或紧邻的独立修复提交；保持来源准备先于使用，测试与其语义一致，不改写不相关源码内容。

改 refs 前检查两个仓库的本地/远端分支、tags 和 worktrees，在同级参考目录保存并验证 Git bundle 或可恢复 ref、未提交/未跟踪工作及旧新提交映射；完成后校核最终整树与预期文件，保留旧 SHA 对应的 CI 证据。本地重写不包含强制推送、远端删除或仓库重建授权。

最初的来源决策侧会话仅调整文档；随后按用户追加授权，侧会话完成 fork 修复、独立回归、正常推送及 PR 更新，没有改写历史或强推。主会话负责新项目的来源工具、Rust 同步、验证及本地历史整理。完整门禁见[计划 §14.3](../plans/maafw-screencap-extraction-plan.md#143-三阶段验收与-pr-专项矩阵)和[§16](../plans/maafw-screencap-extraction-plan.md#16-实施阶段与退出条件)。
