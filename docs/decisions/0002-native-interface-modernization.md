# ADR 0002：迁移旧兼容接口与原生捕获接口现代化

日期：2026-10-27。状态：用户要求纳入实施计划，迁移与验收尚未完成。影响阶段：P2 验收后的 P3 原生接口迁移，P4 策略及 P5 绑定/分发验收；仅性能调优继续按 P6 测量门禁执行。

本 ADR 补充[技术选型 R1–R8](interactive-technology-selection.md)及 [ADR 0001](0001-gdi-virtual-desktop-capture.md)，不替代既有阶段顺序、平台绑定或独立 GDI 全虚拟桌面范围。替代关系：无；各项迁移相对于冻结 P 基线形成可追溯的产品 E 差异，不修改 U/P 快照。

## 问题与决定

固定上游包含为旧系统兼容保留的 GetBitmapBits、已弃用的 PipeWire 数字节点目标选择，以及仍受支持但存在更新方案的 DXGI、FramePool 和位图路径。依赖采用最新版本并不会自动改变这些调用。

将逐项迁移纳入产品实施范围，具体原生选择和完成条件以[原生接口现代化设计](../design/native-interface-modernization.md)为权威清单。明确弃用的用法优先移除；仍有效接口根据布局、所有权、线程、格式和来源要求迁移，不能把“存在更新接口”当作旧接口已弃用或无条件更快的证据。

新接口作为对应产品路径的实现目标。P3 核验并冻结每项最低 SDK、运行时和服务端能力；缺失时明确报告不支持。确需保留兼容调用时记录适用环境、选择条件和验证结果，不静默降级，不以 U/P/E feature 或重复产品后端维持两套语义。Wlr 与 ExtImage 是不同服务端协议能力，按独立方法及来源约束协商，不属于复制两套 U/P/E 实现。

U/P 继续保留上游的接口选择、转换时点、缓存、窗口副作用和原生退出行为；P0/P1 可以记录接口现状及缺口，不提前替换。迁移后的平台能力、默认值和输出范围只有通过原生及消费验收后才可声明。

## 范围与取舍

- GDI、ScreenDC 和 PrintWindow 的产品像素路径统一采用显式 DIB，保持三者的捕获来源及窗口行为区别。CreateCompatibleBitmap 本身仍受支持，迁移动机是显式像素布局及 CPU 访问，不是把所有 GDI 函数列为弃用。
- DXGI 工厂、适配器、device 与 duplication 联合升级；新增格式按能力公布，不连带承诺 HDR 或所有原生格式。
- FramePool 转向 CreateFreeThreaded，并移除经核验没有捕获用途的 swap chain；线程所有权和回调排空保持明确，不借此自动引入 P6 的事件唤醒优化。
- PipeWire 迁移目标选择和等待路径；Wayland 增加 ExtImage 输出捕获路线。两者都保留授权及来源身份边界，不能因接口迁移换源。
- 上游已弃用的 KWin/WlRoots 兼容导出不成为新 SDK 的兼容义务；原截图职责及授权输入交接仍按 U/P 映射核验，不能以去除旧导出省略迁移范围。
- macOS 已使用 ScreenCaptureKit 的 sample-buffer 截图入口；当前未标弃用的接口不强制切换到 macOS 26 的 captureScreenshot。该能力如有需求单独决定，不扩大本轮最低系统要求。

## 验收与证据

计划第 [11.7 节](../plans/maafw-screencap-extraction-plan.md#117-原生接口现代化)规定实施门禁，第 [14.2 节](../plans/maafw-screencap-extraction-plan.md#142-必需夹具)规定验收。每项记录旧/新入口、最低能力、P 基线差异、失败/清理行为及真实取帧证据；优化收益另行测量。当前只是规划，不表示新接口或新增协议已经实现。
