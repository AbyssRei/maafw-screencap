# C ABI、声明生成与回调契约设计

日期：2026-10-27。状态：设计约束已确认，产品实现与验收待完成；具体公共 SDK 类型、签名、状态编码与生成工具仍在 P2 验收后的 P3 定案。

阶段边界和验收门禁以[实施计划](../plans/maafw-screencap-extraction-plan.md)为准。本文未标明文件的“第 N 节”均指该计划的对应章节；计划保留原章节号并链接详细规则。U/P 继续保持固定上游行为，本文产品设计不提前进入 P0/P1/P2。

## ABI 与语言包装

C ABI 使用区分类型的 opaque handle、固定宽度字段、UTF-8 和明确结果码。
C 头为公共契约来源，Rust 导出使用 `extern "C"`、适用的 `#[repr(C)]`/透明标量布局及当前工具链要求的符号导出属性，CI 核对大小、对齐、字段偏移、符号和回调签名。
C++ 基础 RAII 包装仅调用 C ABI；可选图像适配单独接入调用方 OpenCV。Rust 消费者首选源码 crate 的安全 API，与 C ABI 复用同一核心实现；Rust 类型只用于源码接口，不承诺 Rust 动态 ABI，也不要求 Rust 调用方再次经过 C ABI。

首批接口覆盖 ABI/版本/能力查询、目标与 Session 创建、连接、单帧捕获、Frame 查询/释放、暂停/恢复、资源释放、关闭、错误查询及 custom provider 注册。
原始捕获及像素描述属于基础 C ABI；格式支持按后端/目标查询。转换和 OpenCV 集成使用显式可选的适配入口，不把它们伪装成基础核心保证。
纯 C 与 Zig 消费者可直接读取已声明格式的 Frame，或在调用端接入自备转换实现；首版不提供统一原生转换 C ABI，binding 的 BGR/RGB 请求不满足时返回明确错误，不能静默交付另一格式。
可选策略通过统一 options/policy 协商，并报告缺失能力和未知策略。
库级功能位仅表示查询/调用入口存在；具体方法、目标、环境和策略组合的支持单独报告，不能由一个全局位推断全部后端已实现。

结构定义明确 `struct_size`、必需前缀、reserved 字段与扩展读写规则：只访问调用者提供且本版本认识的字段，输出限制在实际缓冲内。
Rust slice、`Result`、`String`/`Vec`、引用计数对象、trait object、allocator 和内部 enum/struct 转换为契约定义的指针/长度、标记及结果码；外部整数先校验再转为内部枚举，不把任意 C 值直接解释为 Rust enum。
布尔返回值、枚举和函数指针的实际 ABI 宽度由原生消费测试与各绑定共同验证。

内嵌结构一旦进入公共 ABI，其占用空间与后续字段偏移固定；仅增加内层 `struct_size` 不能使原地扩容兼容。
需要独立演进的配置/描述优先使用带尺寸的间接结构、扩展入口或明确预留空间，避免内层追加字段移动外层字段。
分别定义输入声明尺寸、输出容量和实际写入版本的含义，嵌套结构与回调表各自校验；未知必需标记在原生调用和窗口修改前拒绝。
创建/捕获失败时输出句柄置空，其他输出逐接口定义失败时的可读字段；只初始化调用者提供且可写的已知范围，不泄露部分构造对象或未初始化字节。
P3/P5 验证较短合法前缀、过短输入、较大尾部、嵌套版本及新旧头文件/库组合，不能以所有结构尺寸必须完全相等替代扩展契约。

## Custom provider

注册时复制回调表，明确函数/context 的保活、线程和重入责任。
每次 capture 定义所有权接管点：接管后所有成功和失败路径恰好释放一次，未接管时按提供者契约处理。
部分注册、像素 pin、分配和校验失败均可回滚。返回帧验证目标 key、scope、有效字段、几何及精确格式/布局描述，不仅依赖 channels；不支持的格式在接管契约内正确释放并拒绝。
Provider 声明与系统独立验证分别标记；原生时间或内容变化缺少可靠证据时保持未知。

## 回调重入与执行纪律

阶段三的“宿主串行调用”同时约束回调重入。Provider、日志与释放回调均列出可调用入口：
首版允许通过独立句柄请求取消及查询已交付的不可变 Frame；同一 Session 的连接、捕获、暂停、资源释放和关闭不允许嵌套执行。
有返回值的入口检测到不支持的重入时返回明确的忙/状态错误，保持外层操作与主要错误不被覆盖；销毁不与活动调用重入，调用方在回调返回后执行。
日志接收器间接再次产生日志时使用递归抑制或有界队列，不能无限递归；替换/注销回调的完成点包含在途调用排空与 context 保活，不能在回调内同步等待自身排空。
绑定若需将回调派发到宿主事件循环，先验证同步等待关系；不能让阻塞该循环的捕获调用等待同一循环执行回调。
这些约束在 P3 定义，P5 及后续绑定分别验证，不改变 U/P 的原始回调流程。

## 权威输入、生成结果与手写代码

公共 C 头是 ABI 布局、标量值、函数签名和回调表的权威输入。P3 选择具体生成工具，形成以下可重复的生成/核验链，避免引入另一套手工维护的公共结构或通用 schema 作为竞争来源：

| 内容 | 维护位置与规则 |
| --- | --- |
| 公共 ABI | `include/maafw-screencap/`；明确注释、尺寸/扩展规则和版本 |
| 原生声明生成输入 | `build-support/` 下的平台输入，记录 allowlist、target、宏、头文件/协议与生成参数 |
| Rust ABI 原始声明、常量与签名 | 从公共头生成或自动核验，构建结果进入 `OUT_DIR`；不手写漂移的第二份契约 |
| ctypes 原始声明、常量与能力标识 | 由同一公共头派生，在绑定打包暂存区生成并随 binding 交付；布局与真实库共同核验 |
| 导出清单与可选符号检查 | 从同一契约派生/核验，核对最终动态库的实际导出 |
| Rust 安全 API / C ABI 句柄与错误映射 | 手写所有权和输入验证；安全 API 直接使用内部模型 |
| Python 对象、C++ RAII、图像薄适配 | 手写语言语义与资源管理，不由原始声明生成器推断寿命 |

生成输入随完整产品源码交付；原生绑定声明与手写安全资源封装分离并靠近平台后端。生成器的工具要求、净环境源码重建成本和确定性需在 P3/P5 验收，不能为保持同源而隐式增加未声明的基础构建前提。

声明生成不能代替输出范围、整数窄化、输入有效值、回调保活和 ABI 演进测试。符号、常量、布局与调用行为均在独立原生消费者中核验。

内存/异常边界见[Frame 与内存设计](frame.md)，原生通道和注销顺序见[执行模型](../design/execution-model.md)。
