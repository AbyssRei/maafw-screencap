# Frame、像素与内存契约设计

日期：2026-10-27。状态：设计约束已确认，产品实现与验收待完成；具体公共 SDK 类型、签名、状态编码与生成工具仍在 P2 验收后的 P3 定案。

阶段边界和验收门禁以[实施计划](../plans/maafw-screencap-extraction-plan.md)为准。本文未标明文件的“第 N 节”均指该计划的对应章节；计划保留原章节号并链接详细规则。F 按[ADR 0003](../decisions/0003-corrected-fork-extraction-baseline.md)采用修正 fork 的固定行为；修复进入 P1，P2 冻结并验收，本文产品设计不提前进入 P0/P1/P2。

## 公开像素

最终 SDK 首选交付保留已验证取样格式的原始 CPU Frame，不强制每帧统一转换为 BGR8。原始表示像素存储格式，不表示 GPU 句柄、仍被借用的原生映射或端到端零复制。
首批候选为 BGRA8/BGRX8、RGBA8/RGBX8、BGR8/RGB8 与 YUY2；按后端实际完成的组合公布支持，未知或未验收格式明确拒绝，不承诺所有后端均能输出所有格式。
阶段一、二仍保持上游输出；P3 将原格式路径作为最终产品设计落实，BGR8 等统一输出由显式可选适配提供，并单独说明公共契约与基线 F 的差异。

| 描述 | 契约 |
| --- | --- |
| 存储与格式 | 精确格式标识、字节序、通道排列、位深及 packed/plane 信息；首期只开放已验证的 single-plane 布局，不用通道数代替格式 |
| 尺寸与布局 | 实际像素宽高、row stride、有效数据跨度、offset 及方向；与目标几何和实际缓冲一致，行距不默认等于宽度乘通道数 |
| alpha 与颜色 | 区分有效/未使用 alpha、直通/预乘、已知色彩空间与 YUV 范围/矩阵；未知字段带有效性标记，SDR/HDR 和 tone mapping 单独协商 |
| 样本与所有权 | 目标/来源、样本身份、取样时间证据及格式/会话代次随 Frame 保存；复制、转换和数组包装不生成新的捕获样本 |

乘加、跨度、offset 和类型转换先进行受检计算；公开行填充及无意义字节按约定初始化，不把原生 padding 当作有效图像对外暴露。
对外缓冲的整个可读跨度只包含目标像素和已定义填充；核心以必要的逐行复制等操作完成窗口客户区隔离，不能只返回全桌面内存中的 ROI 起始地址，再由 binding 隐藏其余内容。
YUY2 等共享色度格式的范围提取必须满足像素组对齐；无法精确隔离目标时明确拒绝，或由显式可选转换路径处理，不能扩大公开范围或按 RGB 字节规则裁剪。
原生缓冲在 Unmap、Unlock 或归还 producer 前完成必要复制或取得可证明的所有权；原始路径同样保证 Frame 独立寿命，不为去除转换而延长无界映射或占用 producer 队列。

Frame 默认不可变，跨后续捕获、暂停、资源释放、格式变化和 Session/Runtime 销毁保持有效。
绑定提供可写数组或 Buffer 时使用独立副本，缓存存储与调用者可写别名隔离；原格式和转换后的 Frame 均遵循此约束。
外部地址的真实可读性由提供者负责；核心发布 Frame 前校验声明的尺寸、stride、长度、offset、格式、对齐和算术范围，不能将安全校验转移给 OpenCV 或宿主算法。

## 全虚拟桌面帧

作为 P3 产品扩展，Frame 的目标描述须能表达[全虚拟桌面来源](lifecycle.md#全虚拟桌面目标)。输出矩形是已验证活动逻辑显示区域的包围框，保留可为负数的桌面原点、同次布局快照及画布内的有效覆盖区域；像素 `(0, 0)` 对应桌面原点，不默认对应桌面坐标 `(0, 0)`。

活动显示区域之外的布局空隙定义为黑色，行填充和 BGRX 未使用字节初始化为零；原生未定义内容不得直接暴露。空隙不是捕获失败的替代标记；原生调用失败或布局不一致时不以填黑伪造完整成功。首期格式目标是已验证的 BGRX8，alpha 标为未使用，颜色证据不足时保持未知。

屏幕 DC 单次取图的结果不携带伪造的逐屏 sample ID、时间戳或同一呈现时刻保证。记录可取得的 API 取样区间及其证据范围；布局整理、复制与转换不生成新的捕获样本。具体公共字段和 ABI 表达在 P3 定案，既有独立寿命、不可变性、容量和转换规则同样适用。

## 内存、清理与失败边界

按对象和操作划分所有权与寿命，Frame 存储及释放状态独立于 Session 临时内存；核心状态与缓冲访问优先使用安全 Rust，由局部封装承担原生所有权接管。
原始帧分配、布局描述、复制与矩形计算由核心管理，不依赖 `cv::Mat`；可选适配自行管理输出，不将 OpenCV 的隐式分配计入核心分配控制保证。
默认 C API 在库内部分配并由对应释放接口回收；Rust 源码 API 的所有者封装复用同一释放逻辑，不能把内存交给宿主不匹配的 allocator 释放。跨线程释放条件与所需原生执行通道明确写入契约。

RAII/`Drop` 管理通常清理和部分初始化回滚，所有权在发布、注册和线程移交时显式转移；需要报告失败的恢复/close 操作显式返回主要和清理结果，`Drop` 只承担已定义的兜底，不吞掉尚待恢复的窗口状态。
对允许恢复的分配失败使用 `try_reserve`/`try_reserve_exact` 等 fallible 路径，并覆盖帧存储、对象/回调状态、集合增长及错误通知；已取得容量内的写入仍检查长度，不以普通 `push` 等隐式扩容破坏保证。
标准 `Box::new`/`Arc::new` 的默认分配不自动返回可恢复错误，不能承诺用 `catch_unwind` 捕获 OOM；需要可恢复分配的对象采用标准库 `Box::try_new`、`Arc::try_new` 等 nightly 实验 API，集中在必要的内部所有者封装并保留标准 `Arc/Weak` 机制，不维护额外 stable 实现或自行重写通用引用计数。
P0 验证 fallible 构造、部分初始化回滚、注册地址稳定、跨线程释放和回调保活；构造参数内部的隐式分配、错误通知和集合增长也纳入检查，不能仅将最外层 `new` 改为 `try_new` 就宣称完整覆盖。API 与 feature gate 跟进第 5.1 节；相关 API 稳定并通过迁移验收后转回 stable。
完整保证范围包括自有分配与原生 API 返回的失败；系统/宿主分配器本身可能终止进程等边界如实说明，不能将 Rust 类型安全视为全部外部资源失败均可恢复。

已注册的 backend、内嵌 hook、listener、COM delegate 和 callback context 具有稳定地址；适用处采用独立堆对象，涉及固定地址不变量时使用 `Pin` 或稳定句柄，并核验移动、注销与释放路径。
注销完成且在途回调结束后才能释放；堆分配或 `Pin` 本身不替代该条件。借用的 POD、数组和字符串保持到原生 API 不再访问为止。
Frame、取消句柄、恢复状态或在途回调存活期间，宿主保持原生模块加载；共享引用只保活其实际拥有的对象，不自动保活独立动态模块。
`Send`/`Sync`、原生对象线程归属与 Frame 不可变性分别证明；引用计数与锁不自动赋予外部指针安全性，也不允许仍被宿主持有的帧缓冲被池重用。

可恢复错误、分配失败、无效输入和原生失败通过 `Result` 等明确结果处理，在 C/系统边界映射结果码，并在桥接内部处理原生异常。
panic 不作为正常错误处理；对禁止展开的 C 导出和原生回调边界制定拦截与失败状态规则，采用 unwind 时只在可保证清理与状态有效的边界捕获，禁止异常穿越不允许展开的 ABI。
`panic=abort`、终止进程的 OOM 和外部未定义行为不能由 `catch_unwind` 恢复；不能将切换 abort 作为缩小包体积的默认优化，panic 后是否允许继续使用 Session 必须明确。
尺寸、偏移、窄化、对齐及跨度校验在所有 profile 中保留，panic、索引 trap 和 debug assertion 不承担输入验证职责。
回调兜底的最小错误记录与等待唤醒不依赖日志成功或再次分配，避免分配失败进入第二次不可恢复失败。

## 可选转换与调用端视图

基础 binding 负责核心 C ABI、Frame 寿命和像素描述，并随对应语言分发薄适配代码；OpenCV、NumPy 与框架功能按需启用，依赖由调用方已有环境提供，不成为基础捕获的强制依赖。
首版共享格式定义、转换参数语义、校验规则和测试夹具；各语言适配只完成公开 API 映射、视图和资源管理，不重复实现转换 kernel，不预先建设通用插件框架或共享转换 ABI。
转换接口存在与当前具备转换能力分别查询；无可用实现时仅保证原始帧交付，不保证统一格式转换，不能以未验证的标量回退伪装成已兑现的优化路径。
适配先读取并校验实际格式、布局和颜色证据，再选择转换；转换所需的颜色信息缺失时，要求显式声明或报告不支持，不能用后来协商的格式解释旧 Frame。

独立共享转换模块只作为后续候选，至少由以下一项实际需求触发：C/Zig 等消费者明确需要项目提供统一转换；多个 binding 出现值得集中维护的大量重复逻辑；或端到端基准证明共享原生融合是达到目标所必需。
触发后单独比较新增构建/分发、依赖共存、所有权和性能成本，再决定是否交付及采用何种链接方式；随包裁剪 OpenCV 亦在该决策中评估，不因预留边界自动实施。
F 的最小验收 binding/适配器及必要桥接只服务迁移与对照验收，不是产品共享转换模块，首版不将其冻结为供消费者调用的转换 API。

借用视图持有真正拥有像素的 Frame，所有视图退出后才释放底层状态；只保存裸地址、创建 `cv::Mat` 头或 NumPy 视图不等于自动保活原生 Frame。
只读接口在可兑现不写入契约时共享像素；不能维持只读约束的通用可写 Mat/数组默认使用独立副本，不能仅用 const 头或包装器名称宣称不可变。
异步转换/推理在完成前保留输入及所需模块，不能因函数已返回或用户关闭 Session 就提前释放；GPU 句柄共享与设备同步作为后续独立扩展，不由 CPU 视图接口隐式承诺。

转换结果保留原 Frame 的来源、sample ID、取样时间与代次，附目标格式及转换完成信息；转换失败单独报告，不污染核心捕获错误、有效原始帧或缓存。
转换缓存如存在，按原样本/格式代次、目标格式与完整转换参数区分，并纳入容量核算；纯包装和转换不得标为 NEW 样本。

## 存储交接与配额归属

原生缓冲到独立 CPU 样本再到 Frame 的唯一交接边界见[架构设计](../design/architecture.md)。CPU 样本发布时复用其拥有的存储，不默认增加一次完整复制；原生租约与 producer 归还责任不进入 Frame。

帧存储的容量记账状态随最后一个实际所有者存活，即使 Session 或 Runtime 外层句柄已释放。缓存与多个只读视图引用同一存储时，物理字节与逻辑持帧数分别核算，不能对同一存储重复记账或提前归还额度。转换输出独立核算；具体配额及默认值按计划第 12.3 节在 P3/P4 决策。

本文的内存与清理规则也适用于会话、回调状态和 ABI 所有者；它们不赋予原生对象额外的线程能力。样本身份、新鲜度和容量策略仍以计划第 12 节为权威定义。
